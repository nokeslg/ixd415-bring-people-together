# User Testing

I user tested in two separate groups.

---

## Session A: 3 people
**Task:** Get a lunch group going.

**What they did**
- All three players signed in with a name and an emoji.
- All three selected **Get a random group**, then selected **Lunch**.

**What worked**
- The countdown gave users clear expectations.
- Names stayed hidden until the group formed.
- Users understood the overall purpose.
- All users were added to the group, even if they chose Spin instead of Get a random group.

**What didn't work**
- One user selected Get a random group and it defaulted him to a study group, which didn't exist because I was testing with only one active group.
- The group took about 2 minutes to form, with nothing to do while waiting.
- Groups are formed right away with no option like "Join this," which left users feeling a bit confused.

**Takeaway:** The Spin feature isn't very accurate yet.

---

## Session B: 2 people, plus myself
**Task:** One person starts a group; the other finds it and joins.

**What they did**
- One person started a group at Watson.
- The second user signed in and looked for a group.
- Both used the table chat.

**What worked**
- Chat synced both ways instantly.
- Refreshing the page kept users in the group.
- When one user left, the group stayed open for the other user.

**What didn't work**
- The user who created the group got no alert when the second user joined.
- User 2 silently became the host once user 1 left.

**Takeaway:** The prototype lacks confirmation and alerts.

---

## Overall takeaways
- Add alerts and notices when things change.
- Add layers of confirmation.
- Hide groups once they're full.
- Fix Spin so it only matches people to existing groups.
- Add something for users to do or see during the waiting period.
- Make Spin preview the group before joining.
